# 0006 – Agent graph: safety before the LLM, HITL booking, library-owned checkpointer

Status: accepted (Phase 3)

## Context
The assistant now takes actions (booking appointments) and talks about symptoms. It must
(a) send emergencies to emergency services reliably, (b) never book without the user's explicit
confirmation or for the wrong person, and (c) keep conversations, including a booking waiting for
confirmation, across restarts.

## Decision

### 1. Deterministic red-flag rules run before any LLM call; the LLM flag is a second layer
- `guardrails/emergency.py` matches red-flag phrases in English and common German phrasings
  ("Brustschmerzen", "Atemnot", "Schlaganfall", "bewusstlos", "Suizid", ...), NFC-normalised so
  umlauts match however they are typed. A match short-circuits the turn to the emergency message
  (112/911, TelefonSeelsorge) without calling the LLM.
- Rules first because an emergency answer must not depend on an API being reachable, a model
  following instructions, or the absence of prompt injection. They are free, instant, unit-tested
  and auditable. The router's `is_emergency` field catches phrasings the rules miss.
- Tuned for recall: a false alarm costs one extra message ("if this is not acute, I can help you
  book"). General questions with no person involved ("what are the signs of a stroke?") are
  answered with a safety notice in front instead of being short-circuited, because health
  education about emergencies is core to the product.
- Known limitation: no negation handling ("no chest pain" still triggers). Accepted for recall.

### 2. Human-in-the-loop booking with `interrupt()`, side effects only after confirmation
- `booking` proposes one concrete, already-validated slot; `confirm` calls `interrupt()`; only
  `book_appointment` writes. LangGraph re-runs an interrupted node from its start on resume, so
  `confirm` has no side effects at all.
- `book_appointment` re-validates (time may have passed) and relies on the partial unique index
  (ADR 0004) as the final arbiter for races. A lost slot loops back to `confirm` with the next free
  slot after the lost one, as a fresh interrupt.
- The resume value is structured (`True` / `{"confirmed": bool}`), not parsed from free text.
- The patient id comes from the run config (CLI flag now, JWT in Phase 5), never from the model.

### 3. LangGraph's `PostgresSaver.setup()` owns the checkpointer tables
- Tables `checkpoints`, `checkpoint_blobs`, `checkpoint_writes`, `checkpoint_migrations` are
  created and migrated by the library, idempotently, on start-up. They are **not** mirrored in
  Alembic: the library versions its own schema, and copying it into our migrations would fork it
  and break on library upgrades.
- Consequence, found while writing this ADR: Alembic autogenerate *does* propose dropping tables
  that exist in the database but not in our models, so the next autogenerated migration would have
  dropped every conversation. `migrations/env.py` therefore has an `include_name` filter that skips
  library-owned tables, and an integration test runs `alembic check` with the checkpointer tables
  present (it also fails if a model changes without a migration).

### 4. Structured output via `json_schema`, low effort for routing
- `with_structured_output(..., method="json_schema")` uses the API's native structured outputs.
  LangChain's default forces a tool call, which Claude Sonnet 5.5 (the demo model) rejects with 400.
- Routing/extraction run at `effort="low"`: thinking is on by default on Claude Haiku 5.5 and bills as
  output. Measured on Haiku: about 1.5-2.2k input and 50-70 output tokens per turn, ~$0.0002-0.0003.
- Every graph run logs tokens, estimated USD cost and latency (pseudonymised ids, no message text).

## Consequences
- Emergencies are handled even when the LLM is down; the cost is occasional false alarms.
- No booking can happen without an explicit yes, and a slow confirmation can't double-book.
- Conversations survive restarts and deploys; the checkpointer tables live beside ours in Postgres.
- The red-flag list needs maintenance (new phrasings, more languages) and its own tests.
